# 뉴스 기반 글 1편 티스토리 발행

## 사용자 결과

본인이 화면에서 티스토리 계정 정보를 입력하고 분야를 고른 뒤 버튼을 누르면, 선택한 분야의 최신 뉴스를 바탕으로 쓴 글 1편이 본인의 실제 티스토리 블로그에 발행된다. 성공하면 발행된 글을 확인할 수 있고, 실패하면 어느 단계에서 막혔는지 알 수 있다.

앱 수준 전제는 [PRODUCT.md](../../../PRODUCT.md)를 따른다. 이 작업은 그 핵심 루프(뉴스 검색, 글 작성, 썸네일 준비, 티스토리 발행)를 수동 1회로 끝까지 완성한다.

## 범위

- 티스토리 계정 정보(아이디, 비밀번호)와 분야를 입력하는 화면과 "지금 발행" 버튼
- 분야는 정해진 목록에서 하나를 고른다. 목록: 경제, IT·기술, 시사
- 선택한 분야에서 신뢰도 높은 최신 뉴스나 기사를 찾는다
- 그 정보를 바탕으로 전문가 시각의 글 1편을 쓴다
- 글과 관련된 썸네일을 준비해 글 상단에 넣는다
- 사용자의 티스토리 계정으로 로그인해 글을 발행한다
- 진행 상태, 성공, 실패를 화면에 보여준다

## 인수 기준

1. 올바른 티스토리 계정 정보와 분야를 입력하고 버튼을 누르면 본인의 실제 티스토리 블로그에 새 글이 올라온다. 검증은 티스토리 블로그에서 글이 보이는 것으로 한다.
2. 발행된 글은 예시 글(andystudio.tistory.com의 "전쟁 장기화 우려에 기름값 상승…휘발유 1938원")의 구조와 톤을 따른다. 헤드라인형 제목, 이모지가 붙은 소제목 섹션, 상단 이미지, 하단 원문 출처 링크가 있다.
3. 본문은 2,000자 이내이고, 결론으로 끝난다.
4. 글의 근거가 되는 뉴스나 기사는 선택한 분야의 최근 것이며, 하단에 원문 출처가 표시된다.
5. 썸네일 이미지가 글 상단에 보이고 글 내용과 관련 있다.
6. 진행 중에는 버튼이 비활성화되고 진행 중임이 표시되어, 같은 요청이 중복 발행되지 않는다.
7. 발행에 성공하면 화면에 성공 상태와 발행된 글로 가는 링크가 보인다.
8. 티스토리 로그인 정보가 틀리거나, 글 작성이나 발행 단계에서 실패하면 화면에 실패했다는 것과 막힌 단계(로그인, 글 작성, 발행 중 하나)가 보이고, 티스토리에는 글이 올라오지 않는다.
9. 티스토리 계정 정보는 화면, 로그, 오류 메시지 어디에도 노출되지 않는다.

## 확정한 제약과 이유

- 발행은 공식 API가 아니라 브라우저 자동화로 한다. 성공 판단은 실제 티스토리 블로그 확인으로만 한다. 근거는 [tistory-publishing](../../decisions/tistory-publishing.md)에 있다.
- 이번 범위에서는 사이트 로그인을 만들지 않고 본인만 쓰는 화면으로 만든다. 나중에 Supabase 인증을 연결한다. 이유는 가장 위험한 티스토리 로그인과 발행을 먼저 끝까지 검증하기 위해서다.
- 화면은 [ui-composition](../../decisions/ui-composition.md)을 따른다. 일반 UI는 shadcn 구성을 쓰고, 로딩, 실패, 성공, 비활성 상태를 정상 화면과 같은 문법으로 보여준다.

## 가정 (틀리면 알려 주세요)

- 티스토리 계정 정보는 저장하지 않고 요청 때마다 입력한다. 저장은 사이트 로그인과 함께 나중에 정한다.
- 검증은 이번 세션에서 본인의 실제 티스토리 계정으로, 2단계 인증이 없는 상태로 한다.
- 이번 검증은 로컬 개발 서버에서 본인 PC로 실행한다.
- 분야 목록은 경제, IT·기술, 시사로 시작한다.
- 글 1편은 한 번의 버튼 클릭마다 새로 쓰며, 이미 올린 글과의 중복 여부는 이번에 검사하지 않는다.

## 범위 밖과 이유

- 하루 3번 구간별 랜덤 시각 발행: 수동 1회 발행이 되는지 확인한 뒤 붙인다.
- 사이트 로그인, 구독, 결제, 여러 사용자: 이번 결과의 검증과 무관하고 Supabase 연결과 함께 다룬다.
- 티스토리 계정 정보 저장: 보안 결정이 필요해 사이트 로그인과 함께 다룬다.
- 배포 환경에서의 실행: 실행 환경이 정해지지 않아 보류한다.

## 보류한 결정

- 배포 환경에서 브라우저 자동화를 어디서 어떻게 돌릴지. 그때까지는 로컬 실행만 지원한다. 이 결정은 스케줄 발행 작업 전에 정한다.
- 티스토리 계정 정보의 저장 방식과 보호 방식. 그때까지는 저장하지 않는다.

## 남은 위험

- 카카오 로그인의 보안 절차나 봇 탐지, 티스토리 화면 변경으로 로그인이나 발행이 막힐 수 있다. 이전에 GitHub Actions에서 로그인이 실패한 적이 있어 가장 큰 위험이다. 이 방식이 티스토리 약관상 허용되는지는 확인하지 못했다.
- 글이 정확하고 어색하지 않은지는 사람이 읽고 판단해야 하며, 자동 검증으로 보장되지 않는다.
- 로컬에서 성공해도 배포 환경에서는 로그인이 막힐 수 있다.
